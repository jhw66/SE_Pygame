# 第四天 · 第一批：箭头飞出动画

本批基于第三天的路径检测、点击消除和失误限制，增加成功飞出动画。
本批结束后先运行、阅读和实验，再继续碰撞变色、失败状态整理、重新开始。

## 1. 从“马上删除”变成“移动结束再删除”

第三天：点击 → 判断路径 → 把格子设为 None。

这一批：点击 → 判断路径 → 建立动画记录 → 每帧移动 → 整支箭头离开 → 把格子设为 None。

`game_logic.py` 中的判断规则没有改变，改变的是成功点击后的处理顺序。

## 2. 用字典记录一个动画

`main.py` 中的 `flying_arrow` 有两种值：

- `None`：没有正在播放的飞出动画，可以接受点击。
- 一个字典：保存 `row`、`col`、`direction`、`x`、`y`。

行列号记录原格子，方便结束时删除；x、y 记录当前屏幕像素位置，供绘图使用。
原格子不随动画变动，显示坐标则每帧变化。

例如第 4 行第 4 列（下标为 3、3）的向右箭头，初始中心为 (560, 420)。
它向右飞时，只增加 x；动画完成时清空的仍是 `board[3][3]`。

## 3. 时间、速度和位移

主循环开头：

```python
dt = clock.tick(60) / 1000
```

`tick(60)` 限制帧率，并返回距上次调用经过的毫秒数；除以 1000 后得到秒。
60 是帧率上限，不表示电脑每秒一定恰好绘制 60 帧。
原先循环末尾的 tick 已移除，每帧只调用一次。

移动函数：

```python
dr, dc = DIRECTIONS[arrow["direction"]]
arrow["x"] += dc * FLY_SPEED * dt
arrow["y"] += dr * FLY_SPEED * dt
```

当前速度为每秒 320 像素。如果一帧经过 0.016 秒，则移动 5.12 像素。
朝右时 dc=1、dr=0，因此 x 增加、y 不变；朝上时 dr=-1，因此 y 减少。
这里保留浮点坐标，避免每帧取整导致速度偏差。

更新代码放在事件循环外面：没有鼠标事件时也必须继续移动。
游戏主循环始终执行“处理事件 → 更新位置 → 清屏并绘制”。

资料：[Pygame Clock.tick 官方说明](https://www.pygame.org/docs/ref/time.html#pygame.time.Clock.tick)。

## 4. 为什么没有画出两个箭头

动画期间棋盘仍保留原数据，但 `draw_arrows()` 会跳过正在飞出的那一格。
主循环再根据动画字典中的 x、y 单独绘制移动箭头。
每帧开头清空画面后重新绘制，所以不会留下运动轨迹。

移动箭头绘制时临时设置棋盘裁剪区域，离开棋盘的部分不显示，避免遮盖标题与状态栏；
画完立即恢复裁剪区域，其他界面文字照常绘制。

## 5. 什么时候算完全离开

以向右为例：

```python
return arrow["x"] - ARROW_EXTENT >= board_rect.right
```

当箭头最左端也超过棋盘右边界，才认为整支箭头离开。
`ARROW_EXTENT = 24` 是包含线条宽度的保守半尺寸，配合当前箭头图形使用。
如果以后扩大箭头尺寸，这个值也需要随之调整。

动画完成后，主循环依次清空原格、将 `flying_arrow` 设回 None、更新文字。
剩余箭头数量仍从棋盘统计，因此只在动画完成后减 1。

## 6. 为什么动画中暂时不接受其他点击

这一版一次只记录一个移动箭头。动画期间忽略棋盘点击，防止新点击覆盖旧动画，
也避免对仍在飞出的箭头重复操作。关闭窗口事件仍然正常处理。
碰撞点击维持第三天行为；短暂变色与碰撞计时属于下一批。

## 7. 自己运行与实验

在项目根目录的 PowerShell 执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

1. 点击第 4 行第 4 列的向右箭头，观察移动过程和数量变化。
2. 关闭后重新启动，点击第 4 行第 2 列的向下箭头，比较方向。
3. 飞出期间快速点击其他箭头，确认没有额外消除或扣机会。
4. 将 `FLY_SPEED` 从 320 暂时改成 160，预测动画时长，再运行验证。
5. 实验结束恢复 320，或记录你决定采用的新速度。

可以尝试回答：为什么不在点击后立即删除？为什么更新放在事件循环外？
为什么判断中心越界还不够？为什么行变化量对应 y，而列变化量对应 x？
