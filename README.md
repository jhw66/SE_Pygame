# 一箭又一箭

使用 Python 3.12 和 Pygame 2.6.1 的箭头消除游戏。支持自由行列数、单格/直线/弯曲箭头、头部点击、碰撞后原路返回，以及大棋盘缩放拖动。

## 安装与运行（Windows PowerShell）

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

默认仍为 5×5、13 支单格箭头，这只是默认配置，不是尺寸限制。查看新规则可直接运行：

```powershell
# 8×8 混合箭头；固定种子可复现同一系列题目
.\.venv\Scripts\python.exe main.py --level examples/mixed.json --seed 18

# 25×25 大棋盘：先看全景，再滚轮放大操作
.\.venv\Scripts\python.exe main.py --level examples/large.json --seed 18

# 手工演示：点击第 3 行、第 4 列的头部，会先前进再碰撞返回
.\.venv\Scripts\python.exe main.py --level examples/manual.json

# 自由配置矩形棋盘，不限于示例尺寸
.\.venv\Scripts\python.exe main.py --rows 7 --cols 10 --arrow-count 25 --min-length 1 --max-length 6 --turn-probability 0.4
```

`--level` 与行列/形状命令行参数不能混用；修改 JSON 或使用命令行参数二选一。`--seed` 可与两种入口配合。

## 操作与规则

- 左键单击松开时选中**头部所在整格**。该格中的空白也有效，不要求精确点击三角形；其他身体格、空格、右键均不触发操作，也不扣机会。按住左键移动超过 6 像素视为拖动，不会误触发消除。
- 尖端沿朝向直行，身体沿原路径依次跟随。身体仍然占用格子，能够阻挡其他箭头。
- 可以退出时，整支箭头完全离场后才减少数量；最后一支离场后通关。
- 受阻时，箭头先前进到首次障碍处，变红、扣一次机会，停顿 0.1 秒，再沿原路退回原位。相邻障碍也有短距离移动，第三次碰撞完成返回后才失败。
- 动画期间不接受其他棋盘点击；缩放、拖动和关闭窗口仍有效。速度随棋盘行列规模增大而提高，并按实际路程加速：完整消除最多 1 秒；碰撞的前进、0.1 秒停顿及原路返回合计也不超过 1 秒。缩放不会改变动作时长。
- 滚轮以鼠标位置为中心缩放。放大后可按住左键或中键上下左右拖动；也可以用方向键平移、Shift＋滚轮左右滑动，或使用触控板/鼠标的横向滚轮。点击“全景”恢复完整展示。格子小于 24 像素时仅供概览，需要放大后才能点击。
- 每支箭头从 10 色调色板中随机分配颜色，整支身体和尖端颜色一致。颜色在当前题目中固定，缩放、移动和重开都不会重新变色；换题重新配色。碰撞时临时变红，返回后恢复原色。颜色只用于区分箭头，不影响规则。
- 默认采用沉浸式布局：棋盘在整个窗口正中按比例尽量铺满，正方形棋盘在宽屏上几乎占满窗口高度。小棋盘的全景不再受每格 80 像素限制。
- 左右自然留白只保留剩余箭头、机会、必要状态以及换题、重开、全景按钮和简短操作说明；没有足够留白时自动改用上下窄工具条，所有控件均不遮挡棋盘。放大后仍在独立棋盘区域内拖动，窗口尺寸变化会重新布局。
- “重新开始”恢复**当前题目**和机会，保留视图位置；“换一题”用**相同配置**生成新布局并恢复全景。两者都会取消旧动画。手工关卡禁用换题。
- 生成在后台进行。失败时保留当前棋盘并显示原因；可以调整配置后重新启动，或再次尝试换题。

## 设计关卡

随机关卡 JSON 示例：

```json
{
  "rows": 16,
  "cols": 20,
  "arrow_count": 100,
  "min_length": 1,
  "max_length": 8,
  "turn_probability": 0.35
}
```

行列数、支数和长度必须为正整数，最小长度不能超过最大长度。没有把 4×4 或 25×25 写成规则上下限；更大的密集布局仍需结合生成耗时和显示性能合理配置。

一支箭头的长度是它占用的格数。必须满足 `arrow_count × min_length <= rows × cols`，实际路径也不能相互重叠。8×8 放 50 支箭头只剩 14 格用于额外延长，所以多数箭头必然很短。

`max_length` 是上界，不保证每支都达到它。`turn_probability` 是延长身体时的转弯偏好，不保证成品中弯曲箭头的固定比例；零表示只生成直线。几何空间与可解性约束会影响最终长度及形状。

生成器先构造可解单格布局，再延长箭尾；每次扩展都检查整盘可解性。先满足最小长度，再尝试更长路径。默认最多尝试 100 次布局、耗时预算 5 秒；不满足时明确失败，不偷偷减少支数或最小长度。容量足够只是必要条件，不保证指定形状一定能生成。代码调用可用 `max_attempts`、`time_budget` 调整预算。

手工布局使用 `rows`、`cols`、`arrows`，详见 [examples/manual.json](examples/manual.json)。每支箭头包含：

```json
{"id": 0, "cells": [[3, 1], [3, 2], [2, 2], [2, 3]], "direction": "R"}
```

坐标为**从零开始的 `[行, 列]`**，路径按尾到头排列，最后一个格子就是唯一可点击的头部格。方向取 `U/D/L/R`，多格箭头朝向须与最后一段一致。路径必须逐格上下左右连接，不能越界、重复占格、自交或与其他箭头重叠。加载时会检查完整可解性。

头部也不能穿过自身尚未腾空的身体；若前方格是本步尾部刚腾出的格子，则允许经过。

游玩界面不显示格子像素、初始占用率等设计数据，也不会在加载或换题时自动计算这些指标。需要分析关卡时，可在代码中调用 `levels.level_metrics(board)` 获取占用率、开局可消除支数和解锁轮数。解锁轮数指每轮同时移除当时所有可退出箭头所需的轮数，仅作设计参考；棋盘大不一定更难。

## 代码结构

- `game_logic.py`：不可变箭头路径、棋盘占用、运动预判、纯规则求解和路径采样。
- `game_state.py`：前进、碰撞停顿、返回、失败、通关与重开状态。
- `levels.py`：配置验证、随机生成、手工 JSON 加载和设计指标。
- `board_view.py`：缩放、平移、坐标转换、裁剪及路径绘制。
- `main.py`：窗口事件、后台生成及命令行入口；导入时不会打开游戏。
