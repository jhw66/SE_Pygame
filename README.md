# 一箭又一箭

使用 Python 3.12 和 Pygame 2.6.1 的箭头消除游戏。支持自由行列数、单格/直线/弯曲箭头、头部点击、碰撞后原路返回，以及大棋盘缩放拖动。

## 安装与运行（Windows PowerShell）

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

启动后进入五关首页，直接点击已解锁的关卡进入挑战。所有关卡参数在 `config/campaign.json` 中设置；可用 `--seed 18` 固定随机种子以复现题目。

## 五关挑战

五关配置从 `config/campaign.json` 读取，可调整每关的 `rows`、`cols`、`arrow_count`、`lives` 和形状参数；`lives` 为 1～20 的整数。保存后在首页点击“重载配置”；内容改变会重置通关进度，管理员权限保留。五关继续使用当前多格路径生成器，最小长度为 1、最大长度为 6、转弯偏好为 0.45。密集布局受剩余格子限制，成品混合单格、直线和弯曲箭头，不保证每支都能延长到最大长度。

- 初始仅第一关开放，实际清空一关才开放下一关。已通关关卡再次进入、重开或换题后，“下一关”仍可使用；未通过的关卡需要先通关。管理员可直接使用“下一关”跳到下一关，不计为通关。
- “重新开始”恢复本题并保留观察位置和配色；“换一题”只更换当前关题目，不跳关。
- “返回首页”结束当前题并取消后台任务，保留本次运行的解锁和通关记录；重新选关生成新题。
- 五关都实际完成后才显示“全部五关通关”。管理员直接通过第五关不会自动把前四关标为已完成。
- 关闭游戏后所有进度和管理员权限重置，当前不保存存档。

## 管理员密码：本地 JSON

管理员密码保存在 `config/admin.json` 中。打开这个文件，把 `password` 的空字符串改为你自己的密码：

```json
{
  "password": ""
}
```

空密码表示尚未设置，没有内置默认密码。本地 `config/admin.json` 和 `config/campaign.json` 已加入 `.gitignore`。仓库提供 `config/admin.example.json`（空密码）和 `config/campaign.example.json`（五关示例）。首次启动时自动从示例创建缺失的本地配置，已有配置不会被覆盖；拉取代码并安装依赖后即可直接运行普通模式。需要管理员功能时，再填写本地密码。

游戏按程序文件所在位置查找配置，不受启动终端当前目录影响。每次打开管理员入口和每次提交密码都会重新读取 JSON，因此修改并保存文件后，无需重启游戏。文件支持 UTF-8（含 BOM），要求最外层为对象且 `password` 是非空字符串；读取失败或格式错误只显示提示，不影响普通游戏，也不会显示文件中的密码。

首页点击“管理员入口”，输入密码，点击“验证并解锁”或按 Enter。输入以星号显示，Backspace 删除，Esc 返回；密码区分大小写和首尾空格。解锁只在本次运行有效，不会增加实际通关记录。此功能用于本地作业演示，配置文件由本人保管，勿将真实密码放入 README 或公开仓库。

## 操作与规则

- 左键单击松开时选中**头部所在整格**。该格中的空白也有效，不要求精确点击三角形；其他身体格、空格、右键均不触发操作，也不扣生命值。按住左键移动超过 6 像素视为拖动，不会误触发消除。
- 尖端沿朝向直行，身体沿原路径依次跟随。身体仍然占用格子，能够阻挡其他箭头。
- 可以退出时，整支箭头完全离场后才减少数量；最后一支离场后通关。
- 受阻时，箭头先前进到首次障碍处，变红、扣一点生命值，停顿 0.1 秒，再沿原路退回原位。红色爱心随扣血变灰；生命值归零立即弹出“重新开始／回到主页选关”，背景仍可完成返回动画。
- 动画期间不接受其他棋盘点击；缩放、拖动和关闭窗口仍有效。速度随棋盘行列规模增大而提高，并按实际路程加速：完整消除最多 1 秒；碰撞的前进、0.1 秒停顿及原路返回合计也不超过 1 秒。缩放不会改变动作时长。
- 滚轮以鼠标位置为中心缩放。放大后可按住左键或中键上下左右拖动；也可以用方向键平移、Shift＋滚轮左右滑动，或使用触控板/鼠标的横向滚轮。点击“全景”恢复完整展示。格子小于 24 像素时仅供概览，需要放大后才能点击。
- 每支箭头从 10 色调色板中随机分配颜色，整支身体和尖端颜色一致。颜色在当前题目中固定，缩放、移动和重开都不会重新变色；换题重新配色。碰撞时临时变红，返回后恢复原色。颜色只用于区分箭头，不影响规则。
- 默认采用沉浸式布局：棋盘在整个窗口正中按比例尽量铺满，正方形棋盘在宽屏上几乎占满窗口高度。小棋盘的全景不再受每格 80 像素限制。
- 左右自然留白显示当前关卡、剩余箭头、生命值和必要状态，并放置换题、重开、全景、下一关、返回首页按钮。没有足够留白时自动改用上下工具条，所有控件均不遮挡棋盘。放大后仍在独立棋盘区域内拖动，窗口尺寸变化会重新布局。
- “重新开始”恢复**当前题目**和生命值，保留视图位置；“换一题”用**相同配置**生成新布局并恢复全景。两者都会取消旧动画。
- 生成在后台进行。失败时保留当前棋盘并显示原因；可以调整配置后重新启动，或再次尝试换题。

## 设计关卡

`config/campaign.json` 的 `levels` 数组必须保留五项，每项可按如下格式调整：

```json
{
  "name": "自定义关卡",
  "lives": 3,
  "rows": 16,
  "cols": 20,
  "arrow_count": 100,
  "min_length": 1,
  "max_length": 8,
  "turn_probability": 0.35
}
```

行列数、支数和长度必须为正整数，最小长度不能超过最大长度。没有把 4×4 或 25×25 写成规则上下限；更大的密集布局仍需结合生成耗时和显示性能合理配置。

一支箭头的长度是它占用的格数。必须满足 `arrow_count × min_length <= rows × cols`，实际路径也不能相互重叠。8×8 放 50 支箭头只剩 14 格用于额外延长，所以多数箭头必然很短。

`max_length` 是上界，不保证每支都达到它。`turn_probability` 是延长身体时的转弯偏好，不保证成品中弯曲箭头的固定比例；零表示只生成直线。几何空间与可解性约束会影响最终长度及形状。

生成器先构造可解单格布局，再延长箭尾；每次扩展都检查整盘可解性。先满足最小长度，再尝试更长路径。默认最多尝试 100 次布局、耗时预算 5 秒；不满足时明确失败，不偷偷减少支数或最小长度。容量足够只是必要条件，不保证指定形状一定能生成。代码调用可用 `max_attempts`、`time_budget` 调整预算。

## 代码结构

- `game_logic.py`：不可变箭头路径、棋盘占用、运动预判、纯规则求解和路径采样。
- `game_state.py`：前进、碰撞停顿、返回、失败、通关与重开状态。
- `levels.py`：随机布局参数验证与可解关卡生成。
- `board_view.py`：缩放、平移、坐标转换、裁剪及路径绘制。
- `campaign.py`：五关配置、会话内解锁与通关记录、本机 JSON 管理员验证。
- `main.py`：首页、管理员输入、窗口事件、后台生成及命令行入口；导入时不会打开游戏。
