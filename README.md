# 一箭又一箭 · 五关挑战

使用 **Python + Pygame** 开发的点击式箭头解谜游戏。观察箭头的朝向与阻挡关系，点击头部，让箭头依次抽出并离开棋盘；碰到障碍会原路返回并扣除生命值，清空棋盘即可通关。

当前版本支持单格、直线和弯曲箭头，提供五关挑战、可解随机出题、固定种子复现、缩放拖动，以及用于本地演示的管理员选关功能。

仓库：[jhw66/SE_Pygame](https://github.com/jhw66/SE_Pygame)。

## 1. 游戏简介

- **五关挑战**：普通模式从第一关开始，实际通关后解锁下一关。
- **可解随机出题**：按配置生成布局，检查完整消除顺序；生成失败会提示原因。
- **多种箭头形状**：单格、跨多格直线和弯曲箭头使用同一套规则。
- **飞出与碰撞反馈**：头部沿朝向前进，身体沿原路径跟随；受阻后变红、扣血、停顿，再退回原位。
- **大棋盘操作**：滚轮缩放，左键或中键拖动，方向键平移，全景复位。
- **关卡配置**：通过 JSON 调整名称、尺寸、箭头支数、生命值和形状参数。
- **管理员模式**：验证本地密码后，本次运行中可直接选择全部五关。

游戏在本机桌面窗口运行，安装完成后游玩无需网络。当前没有存档功能：关闭程序后，通关记录和管理员权限重置；本地配置文件保留。

## 3. 从 GitHub 下载到第一次运行

### 3.1 安装 Python 和 Git

1. 从 [Python Windows 下载页](https://www.python.org/downloads/windows/)安装 Python 3.12 的 64 位版本。使用传统安装器时，勾选将 Python 加入 PATH 的选项。
2. 选择 Git 克隆方式的用户，从 [Git for Windows 官方下载页](https://git-scm.com/install/windows)安装 Git。
3. 安装后重新打开 PowerShell，检查：

```powershell
python --version
git --version
```

如果 `python` 无法识别，但 `py -3.12 --version` 能运行，创建虚拟环境时改用 `py -3.12 -m venv .venv`。已安装多个 Python 版本时，也可用这种写法明确选择 3.12。

### 3.2 获取项目：两种方式选择一种

**方式 A：Git 克隆，推荐用于以后持续更新。**

在资源管理器中打开准备存放项目的文件夹，在地址栏输入 `powershell` 并回车，逐行执行：

```powershell
git clone  https://github.com/jhw66/SE_Pygame.git
cd SE_Pygame
```

首次获取项目使用 `clone`；已经有本地 Git 仓库后，才使用 `pull` 更新。[Git clone 文档](https://git-scm.com/docs/git-clone)

**方式 B：下载 ZIP，适合只想运行游戏。**

1. 打开 [项目仓库](https://github.com/jhw66/SE_Pygame)。
2. 点击 **Code → Download ZIP**。
3. 完整解压，进入实际包含 `main.py`、`requirements.txt` 和 `config` 的目录。
4. 在这个目录的资源管理器地址栏输入 `powershell` 并回车。

不要在压缩包内直接运行文件。ZIP 不包含 Git 历史，以后更新需重新下载，并自行保留本地配置。

### 3.3 创建环境并安装依赖

确认终端位于包含 `main.py` 的项目根目录，执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`.venv` 是项目独立的 Python 环境。直接调用其中的解释器就能运行，不要求先激活，也不用修改 PowerShell 执行策略。[Python 虚拟环境说明](https://docs.python.org/zh-cn/3.12/library/venv.html)

检查安装结果：

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip show pygame
```

### 3.4 第一次启动

```powershell
.\.venv\Scripts\python.exe main.py
```

启动后显示五关首页，点击第一关即可开始。首次启动会自动从模板创建缺失的本地配置：

| 仓库提供的模板 | 自动创建的本地文件 | 用途 |
| --- | --- | --- |
| `config/campaign.example.json` | `config/campaign.json` | 五关参数 |
| `config/admin.example.json` | `config/admin.json` | 本机管理员密码，初始为空 |

**普通模式无需设置管理员密码。** 已有本地配置不会被覆盖；项目目录需要具备写入权限。

以后只需打开项目目录并执行启动命令，通常无需重新创建环境或安装依赖。关闭游戏窗口即可退出。


## 4. 所有启动方式与种子的区别

### 4.1 不带种子：日常随机游玩

```powershell
.\.venv\Scripts\python.exe main.py
```

每次启动建立一个未指定起点的随机序列，不要求与上次产生相同题目。具体题目在选关或点击“换一题”时生成。

### 4.2 带种子：复现一系列题目

```powershell
.\.venv\Scripts\python.exe main.py --seed 18
```

`18` 是示例整数，可以换成其他整数。种子影响生成题目的随机序列和箭头配色，不是关卡编号，也不会自动开启管理员模式。

| 情况 | 行为 |
| --- | --- |
| 不指定种子 | 各次启动采用未指定的随机起点，适合日常游玩 |
| 指定 `--seed 18` | 固定本次运行的随机起点，便于调试与演示 |
| 同种子重启并执行相同选关、换题顺序 | 在代码、环境、配置相同且生成正常完成时，可复现相同的一系列题目 |
| 同一次运行点击“换一题” | 继续使用随机序列，尝试生成不同于当前关上一题的布局，不会一直重复第一题 |
| 点击“重新开始” | 恢复保存的当前题目，不重新随机生成 |

**种子不是存档，也不是某关的独立题号。** “启动后直接进入第三关”和“先生成第一关再进入第三关”，即使种子相同，第三关也可能不同。返回首页再选关会请求新题；生成取消、失败后重试，也可能改变后续序列。

复现问题时，请记录代码版本、Python 版本、`campaign.json`、种子和选关／换题顺序。生成器有时间预算，不保证跨环境或超时情况下严格复现。程序目前不显示可用于还原未指定种子题目的编号。

### 4.3 查看实际支持的参数

```powershell
.\.venv\Scripts\python.exe main.py --help
```

| 参数 | 作用 |
| --- | --- |
| `--seed 整数` | 设置随机种子 |
| `-h` 或 `--help` | 显示帮助并退出，不打开游戏窗口 |

**命令行目前只有上述参数。** 行列数、生命值和形状修改 JSON；管理员从首页进入。当前没有 `--admin`、`--config`、`--rows`、`--lives` 等参数，也不读取 `ARROW_GAME_ADMIN_PASSWORD` 环境变量。

### 4.4 激活环境、模块方式和编辑器运行

如果 PowerShell 允许执行激活脚本，可在项目根目录执行：

```powershell
.\.venv\Scripts\Activate.ps1
python main.py
```

带种子时改用 `python main.py --seed 18`；结束后可执行 `deactivate`。若激活被拦截，使用 4.1 中完整的解释器路径即可。

在项目根目录，还可选择以下一种模块启动命令：

```powershell
.\.venv\Scripts\python.exe -m main
.\.venv\Scripts\python.exe -m main --seed 18
```

两行分别对应无种子和有种子运行，任选其一。

使用 VS Code、PyCharm 等编辑器时，将解释器设置为项目中的 `.venv\Scripts\python.exe`，运行文件设为 `main.py`，工作目录设为项目根目录；固定种子时，在运行参数中填写 `--seed 18`。其他源码文件是功能模块，完整游戏入口为 `main.py`。

从其他目录启动时，需正确指定解释器和 `main.py` 的路径。程序按源码所在位置查找配置，不会到终端当前目录中寻找另一份 `config`。

## 5. 关卡配置：config/campaign.json

### 5.1 仓库默认五关

以下是 **`campaign.example.json` 的默认值**。实际游戏以本机 `campaign.json` 为准，修改过本地配置后，首页数字可能与表格不同。

| 关卡 | 名称 | 行×列 | 箭头支数 | 生命值 |
| --- | --- | --- | --- | --- |
| 1 | 初识方向 | 5×5 | 20 | 3 |
| 2 | 解除阻挡 | 10×10 | 70 | 3 |
| 3 | 步步推进 | 15×15 | 160 | 3 |
| 4 | 密阵挑战 | 20×20 | 280 | 3 |
| 5 | 箭阵终章 | 25×25 | 450 | 3 |

模板中每关还显式设置了 `min_length: 1`、`max_length: 6`、`turn_probability: 0.45`，允许生成单格、直线和弯曲箭头。

### 5.2 修改与生效步骤

1. 先启动一次游戏，让本地文件自动生成。
2. 用记事本或编辑器打开 `config/campaign.json`。
3. 修改需要调整的值并保存。
4. 回到首页，点击 **“重载配置”**。
5. 查看首页参数是否更新，再选择关卡生成题目。

JSON 最外层只能包含 `levels`，该数组必须保留 **恰好五个关卡对象**。下面是完整合法示例：

```json
{
  "levels": [
    {"name": "初识方向", "rows": 5, "cols": 5, "arrow_count": 20, "lives": 3, "min_length": 1, "max_length": 6, "turn_probability": 0.45},
    {"name": "解除阻挡", "rows": 10, "cols": 10, "arrow_count": 70, "lives": 3, "min_length": 1, "max_length": 6, "turn_probability": 0.45},
    {"name": "步步推进", "rows": 15, "cols": 15, "arrow_count": 160, "lives": 3, "min_length": 1, "max_length": 6, "turn_probability": 0.45},
    {"name": "密阵挑战", "rows": 20, "cols": 20, "arrow_count": 280, "lives": 3, "min_length": 1, "max_length": 6, "turn_probability": 0.45},
    {"name": "箭阵终章", "rows": 25, "cols": 25, "arrow_count": 450, "lives": 3, "min_length": 1, "max_length": 6, "turn_probability": 0.45}
  ]
}
```

### 5.3 字段说明

| 字段 | 含义 | 必填与限制 |
| --- | --- | --- |
| `name` | 名称 | 可省略，默认“第 n 关”；提供时必须为非空字符串 |
| `rows` | 行数 | 必填，正整数 |
| `cols` | 列数 | 必填，正整数 |
| `arrow_count` | 箭头支数，不是占用格数 | 必填，正整数 |
| `lives` | 本关初始生命值 | 必填，1～20 的整数 |
| `min_length` | 每支至少占多少格 | 可省略，默认 1；正整数 |
| `max_length` | 每支最多占多少格 | 可省略，默认 1；不小于最小长度的正整数 |
| `turn_probability` | 延长身体时的转弯偏好 | 可省略，默认 0.0；0～1 的有限数值 |

模板显式填写的形状值与“省略字段时的默认值”不同。比如删除 `max_length` 后，默认上限会变成 1，而不是模板中的 6。

必须满足以下容量条件：

```text
arrow_count × min_length <= rows × cols
```

数值不要写成字符串，如用 `"lives": 3`，不要用 `"lives": "3"`。正整数字段也不接受 `3.0` 或布尔值。JSON 不支持注释或末尾多余逗号，关卡对象不接受未定义字段。

### 5.4 单格、直线与弯曲箭头设置

以下是每个关卡对象中的参数组合，不是另外的启动命令：

| 希望得到的形状 | 参数设置 |
| --- | --- |
| 基础单格箭头 | `min_length: 1`、`max_length: 1`、`turn_probability: 0` |
| 直线箭头，可包含单格 | 如 `min_length: 1`、`max_length: 6`、`turn_probability: 0` |
| 每支至少两格的直线 | 如 `min_length: 2`、`max_length: 6`、`turn_probability: 0`，同时确保容量足够 |
| 允许弯曲的混合箭头 | 如模板中的 1～6 格、`turn_probability: 0.45` |

`max_length` 是上界，不保证每支都达到它。转弯偏好也不是成品中弯曲箭头的固定比例；空间与可解性会影响最终形状。例如 5×5 放 20 支箭头只剩 5 格用于延长，大部分箭头自然较短。

棋盘可以是长方形，没有把 25×25 写成上限。较大或密集配置可能生成缓慢；容量满足只是必要条件，不保证形状要求一定能在预算内完成。

### 5.5 重载、进度和生成失败

- **有效参数改变**：重置本次运行的通关和普通解锁进度，保留已取得的管理员权限。
- **有效参数不变**：例如只改缩进，进度不重置。
- **重载配置错误**：提示原因并保留上一次有效配置；首次启动没有有效配置时无法选关，修正后再重载。
- **只修改模板**：已有 `campaign.json` 时不会自动套用模板，应修改本地文件。

生成在后台进行，默认最多尝试 100 次布局，时间预算为 5 秒。生成失败会显示原因；换题前已有棋盘会保留，首次选关尚未生成成功则没有可玩的棋盘。可以重试，或回首页修改、重载配置后选关。程序不会偷偷减少箭头支数或最小长度。

尝试次数和时间预算属于 `levels.py` 中生成函数的参数，当前未开放为 JSON 字段或命令行参数。普通用户可优先减少支数、减小长度要求，或在合理范围内扩大棋盘。

## 6. 管理员模式：设置密码与自由选关

### 6.1 设置密码

首次启动后，打开 `config/admin.json`，初始内容如下：

```json
{
  "password": ""
}
```

将双引号中的空内容替换为自己设置的密码并保存。密码必须是字符串，不能留空或只包含空白；双引号不可删除。使用 UTF-8 保存，带 BOM 的 UTF-8 也支持。

项目**没有内置默认密码**。已有 `admin.json` 时，修改 `admin.example.json` 不会改变当前密码。

### 6.2 进入管理员模式

1. 用普通或带种子的命令启动游戏，两者均支持管理员功能。
2. 首页点击 **“管理员入口”**。
3. 输入本地 JSON 中设置的密码，输入内容以星号显示。
4. 点击 **“验证并解锁”**，或按 **Enter**。
5. 验证成功返回首页，显示全部关卡已解锁，点击任意关卡挑战。

输入时按 **Backspace** 删除，按 **Esc** 或“返回首页”取消。密码区分大小写，也保留首尾空格。每次进入管理员页面和提交验证时都会重新读取文件，保存修改后可直接重试，无需重启。

### 6.3 权限范围与生命周期

- 可以直接进入五关；游戏中满足其他条件时可用“下一关”跳关。
- 失败弹窗出现时需先重开或返回首页，不能直接穿过弹窗跳关。
- 不增加生命值、不免除碰撞、不自动消除箭头。
- 不自动添加“已通关”记录。直接通关第五关不会把前四关视为完成。
- 权限仅本次运行有效，重启后需再次验证；当前没有单独的管理员退出按钮。
- 修改密码不会撤销当前进程已取得的权限，需要清除权限时关闭并重启程序。

这是本地学习和演示功能，密码明文保存在本机 JSON 中，不是联网账号系统。`config/admin.json` 已被 Git 忽略，请保留该设置，不要强制提交真实密码。

## 7. 游戏操作说明

### 7.1 首页与选关

首页显示每关名称、尺寸、箭头支数、生命值和状态：

| 状态 | 含义 |
| --- | --- |
| 未解锁 | 普通模式不能进入，需先通关前一关或验证管理员密码 |
| 可挑战 | 可以进入，选关后生成题目 |
| 已通关 | 本次运行中实际清空过该关，可再次挑战 |

普通模式最初只开放第一关。管理员验证后可选全部关卡。首页“重载配置”用于应用本地关卡设置。

返回首页会结束当前题目，但保留本次运行的关卡进度；再次选关会生成新题，不恢复之前未完成的那盘。

### 7.2 游玩与消除

1. 观察箭头尖端朝向及前方阻挡。
2. **点击头部所在格子并松开左键**。头部格中的空白也有效，不必精确点中三角形。
3. 能通过时，头部沿方向前进，身体沿原路径跟随；整支离场后数量才减 1。
4. 受阻时前进到首次障碍处，变红并扣 1 点生命值，停顿约 0.1 秒，再原路退回。
5. 清空全部箭头后显示本关通关，通过“下一关”继续。

其他箭头的身体和头部都能形成阻挡。点击身体格、空格、棋盘外或使用右键，不触发消除，也不扣生命值。十色配色用于区分箭头，不影响规则；碰撞时临时变红，返回后恢复原色。

左键按下与松开需位于同一格，位移达到 6 像素会被视为拖动。动画期间不接受其他棋盘点击，但可以缩放和平移；失败弹窗出现后操作由弹窗接管。

### 7.3 缩放与移动视图

| 操作 | 效果 |
| --- | --- |
| 鼠标放在棋盘区域，滚轮向上／向下 | 以鼠标附近为中心放大／缩小 |
| 按住左键移动 | 拖动棋盘，达到拖动阈值后不触发消除 |
| 按住中键移动 | 拖动棋盘 |
| 方向键 ↑ ↓ ← → | 平移观察区域 |
| Shift + 滚轮 | 横向平移 |
| 触控板／鼠标横向滚轮 | 横向平移 |
| “全景”按钮 | 恢复完整棋盘视图 |
| 拖动窗口边缘 | 调整窗口大小，重新安排棋盘和控件 |

平移主要在放大后发挥作用。格子小于 24 像素时只允许概览，需要放大后点击箭头。棋盘居中显示，控件优先放在左右留白，空间不足时改用上下工具条。

### 7.4 游戏按钮的区别

| 按钮 | 题目和生命值 | 视图与进度 |
| --- | --- | --- |
| 重新开始 | 恢复本题初始布局和生命值，取消旧动画 | 保留当前缩放、平移、配色和通关记录 |
| 换一题 | 同一关配置生成新布局，成功后恢复生命值 | 恢复全景、重新配色，保留关卡进度 |
| 全景 | 不改变题目和生命值 | 恢复全盘显示 |
| 下一关 | 进入下一关生成题目 | 普通玩家需已通过当前关；管理员可跳关；生成中或失败弹窗中不可用 |
| 返回首页 | 放弃当前题，取消后台任务 | 保留本次运行的解锁与通关记录 |

普通玩家已通过某关后，再次进入、重开或换题不会撤销其通关记录，因此满足其他条件时“下一关”仍可用。

### 7.5 通关与失败

- **本关通关**：最后一支箭头完全离场后，状态区显示“本关通关”，点击“下一关”继续，不自动跳走。
- **全部通关**：五关都在本次运行中实际完成后，显示“全部五关通关”。此时在第五关，“下一关”变为“重新挑战”，点击进入第一关生成新题，已有通关记录保留。
- **管理员跳关**：只完成第五关时会提示其他关尚未全部完成，需回首页继续挑战。
- **失败**：生命值归零立即弹出“生命值已耗尽”。点击“重新开始”或按 **Enter** 重试本题；点击“回到主页选关”或按 **Esc** 回首页。碰撞返回动画可在弹窗背景继续完成。
- **关闭游戏**：清除会话进度和管理员权限，不删除本地 JSON。

## 8. 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 找不到 `main.py`／`requirements.txt` | 进入包含它们的项目根目录后执行命令 |
| `python` 或 `git` 无法识别 | 检查安装与 PATH，重新打开终端；Python 可尝试 `py -3.12` |
| `No module named pygame` | 用 `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` 安装，并使用同一解释器运行 |
| 激活脚本被禁止 | 使用完整解释器路径，无需激活 |
| 中文变成方块 | 系统需提供微软雅黑、黑体或宋体，安装后重启游戏 |
| `unrecognized arguments` | 用 `--help` 检查；关卡修改 JSON，管理员从首页进入 |
| 管理员密码尚未设置 | 修改 `config/admin.json`，不是模板；空串和全空白均无效 |
| 密码验证失败 | 检查文件是否保存、大小写及首尾空格；不要误存成 `.json.txt` |
| 修改关卡没有变化 | 修改本地 `campaign.json`，回首页重载；错误时仍使用上次有效配置 |
| 五关都不能进入 | 检查 JSON 可读性、五项结构、字段与数值，修正后重载 |
| 点箭头没反应 | 点头部格，确认无动画／生成任务、未触发拖动；格子过小时先放大 |
| 生成失败或超时 | 重试，或降低支数／长度要求、适当增加空间后重载；棋盘过大也会增加计算量 |
| 同种子不同题 | 核对代码、环境、配置及选关／换题／取消生成顺序，种子不是独立题号 |
| pull 后没有采用新默认参数 | 本地配置保留是正常行为，备份后参照新模板调整 |
